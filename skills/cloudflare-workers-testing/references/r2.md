# R2

Seed an R2 bucket with representative object content and metadata. Trigger the Worker operation, assert status and content, and consume every returned R2 or fetch body before test cleanup.

## Vitest plugin

This example assumes the Worker serves `OBJECTS.get("report.txt")` at `/files/report.txt`.

```ts
import { env, exports } from "cloudflare:workers";
import { expect, test } from "vitest";

test("serves an R2 object", async () => {
  await env.OBJECTS.put("report.txt", "ready", {
    httpMetadata: { contentType: "text/plain" },
  });
  const response = await exports.default.fetch(
    "https://example.com/files/report.txt",
  );
  expect(response.status).toBe(200);
  expect(await response.text()).toBe("ready");
});
```

When asserting a Worker write, use `const object = await env.OBJECTS.get(key)`, check for `null`, and consume `await object.text()` or another body reader. Await all R2 operations. The plugin's fake timers do not control the R2 simulator's time.

## Wrangler test harness

Seed through the configured binding after `server.listen()` and after each `server.reset()`:

```ts
const worker = server.getWorker("api-worker");
const env = await worker.getEnv();
await env.OBJECTS.put("report.txt", "ready", {
  httpMetadata: { contentType: "text/plain" },
});

const response = await worker.fetch("/files/report.txt");
expect(response.status).toBe(200);
expect(await response.text()).toBe("ready");
```

Use the same key and binding name that the Worker uses. Check metadata separately when it is part of the contract, such as `response.headers.get("content-type")` for a download route.
